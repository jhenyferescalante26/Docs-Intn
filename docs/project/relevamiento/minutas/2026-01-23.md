2. Observaciones y problemáticas identificadas por área

A continuación, se detallan las principales observaciones identificadas durante el relevamiento, destacándose los puntos más relevantes de la reunión.

2.1. ONM - UMLE

2.1.1. Picos de Surtidores

La reunión dio continuidad al relevamiento iniciado el día anterior sobre Picos de Surtidores. Se avanzó desde la Aprobación de Servicio de Máquina y la Verificación Inicial hacia la Verificación Subsecuente, Periódica y Complementaria, confirmando que todos estos tres últimos procesos siguen los mismos flujos operativos.

Se identificaron las siguientes necesidades para la automatización del proceso:

El cliente debe poder autogestionar completamente sus solicitudes desde el portal web, incluyendo la cancelación de agendamientos, etc.

El precinto y el certificado deben compartir los mismos datos de validación, por ej. QR o ID.

Se confirmó que camión y acoplado deben manejarse con IDs distintos.

Se solicitó acceso al sistema para las áreas de Seguridad y Portería.

Los documentos adjuntos cargados por los clientes deben contar con mecanismos de legibilidad y validación.

Se requiere un control de inventario de precintos, incluyendo estados como usados, disponibles y pendientes.

2.1.2. Básculas

Durante el relevamiento del área de Básculas se definió el flujo esperado dentro del sistema y se identificaron las siguientes necesidades:

El proceso debe estar integrado al portal del cliente, desde donde se realizará el agendamiento.

Se requiere un calendario de agendamientos para la planificación de los servicios.

El sistema debe calcular automáticamente el costo adicional por traslado.

Debe existir un historial de servicios realizados.

El acceso de los técnicos al sistema debe estar limitado, permitiendo únicamente completar o editar los campos que les correspondan.

Se solicitó la limpieza de datos duplicados, ya que actualmente dificulta la búsqueda y gestión de información.

4. Observación general

Los flujos relevados para Picos de Surtidores y Básculas serán utilizados como base para la definición de los procesos a automatizar, quedando sujetos a validación y ajustes posteriores en función del diseño final del sistema
